# 新生手册插图流水线

## 这是干什么的

本项目（厦大新生手册）的插图默认是"待补占位符"（`<figure class="fig-placeholder">`，灰色虚线框 + "插图待补"）。本 skill 把"补图"固化为一条全自动流水线：用户只管把图片丢进源目录，其余（匹配、改名、剪切、配对、构建、验证）全部由脚本 + 本 skill 的步骤完成。

## 目录与文件

| 路径 | 作用 |
|---|---|
| `手册内容/本科/` | 各章 md 源文件（`{章号}_{章节}_p*.md`），内容与占位符的源头 |
| `手册内容/本科/手册插入图片/` | **用户放图的地方**（自然语言命名，随便起名）；构建时会被清空（剪切走） |
| `handbook/ug/build/build_content.py` | 构建脚本：同步源图 + 扫描匹配 + 生成 content.js |
| `handbook/ug/img/` | 规范命名后的成品图（`{章号}-p{页码}-img{序号}.png`） |
| `handbook/ug/img/img-meta.json` | 自动同步图片 → 占位符描述 的映射（配对的关键依据） |
| `handbook/ug/js/content.js` | 生成的站点数据（**勿手改**，由脚本生成） |
| `handbook/ug/index.html` | 引用 content.js / style.css 时带 `?v=N` 版本号 |
| `handbook/ug/css/style.css` | 尺寸规范：`.fig-photo` 宽 80%、`max-width:573px` 封顶、居中；`.fig-icon` 图标 180px 封顶；无说明文字 |

## 核心流程（每次补图都做）

### 1. 确认源图（必须做，勿跳过）
列出 `手册内容/本科/手册插入图片/`，确认用户放进去的图片，**并逐一核对每张图应归的尺寸档位**（图标/装饰小图/大图），必要时加入 `MANUAL_CLASS_OVERRIDES`。

⚠️ 构建脚本会自动同步源目录里**所有**图片——即使本次任务只是删占位符/改文字，只要源目录有新图，构建就会把它们导进去。因此**每次构建前都必须先列源目录**，确认有无新图及其正确档位；若用户没提新图、但源目录有，主动向用户确认（是否同步、什么尺寸档位），不要静默处理。

### 2. 运行构建
```bash
cd handbook/ug/build && python build_content.py
```
（或 `python handbook/ug/build/build_content.py`，脚本用自身路径定位，在哪跑都行）

脚本自动完成：
- **同步**：读源目录 → 自然语言匹配占位符 → 剪切到 `handbook/ug/img/{章号}-p{页码}-img{序号}.png` → 把描述写进 `img-meta.json`
- **构建**：扫描 `handbook/ug/img/` → 每个占位符配对图片 → 生成新的 `js/content.js`

### 3. 更新版本号
把 `handbook/ug/index.html` 里 `content.js?v=N` 的 N +1（若改了 CSS，`style.css?v=N` 也 +1），避免浏览器缓存旧文件。

### 4. 浏览器验证（重要，防止错位）
刷新页面，核对每个应配上的占位符：
- 对应 `figure` 的 class 应为 `fig-photo`，内含 `img`，src 指向正确文件；
- 其余占位符保持 `fig-placeholder` + "插图待补"；
- 重点检查**同一页有多个占位符**的情况（易错位，见下）。

## 命名与匹配规则

### 匹配优先级（find_image）
对每个占位符（章号 num、页码 pid、描述 desc）：
1. `{num}{desc}.png` 精确匹配（中文描述命名，手动的）；
2. 同页候选 `{num}-p{pid}-*` 中，先找 `img-meta.json` 里描述一致的图（自然语言同步的）；
3. 再找无 meta 记录的手动文件（如 `{num}-p{pid}-english-name.png`）按页面顺序消费。
每张图只被消费一次。

### 同步匹配（sync_source_images）
源图文件名去空白/标点后：
- 与某占位符描述**完全相同** → 最高优先级；
- 以章号开头 且 与描述互为子串（如 `04厦门大学嘉庚风格建筑群照片` ↔ 描述 `厦门大学嘉庚风格建筑群照片`）→ 次之；
- 无匹配 → 打印 `!! 无法匹配任何占位符：{文件名}` 并跳过（**务必把这条反馈给用户**）。

**归一化规则**（脚本已内置）：文件名与描述先去除空白、全半角括号、引号、顿号，并把连接词/符号视为等价（`与/和/及`、`+`、`&`、`×`、`/` 均归一为空）。例如 `12易班App图标（蓝底白字易班+小熊）` ↔ `易班App图标（蓝底白字"易班"与小熊）` 可匹配。若用户文件名用了脚本没覆盖的字符导致 `!! 无法匹配`，可先扩展 `normalize_desc` 的正则，再重跑构建。

### ⚠️ 铁律：同页多占位符必须按描述配对，禁止只按页面顺序猜
第 10 页有两个占位符（德旺穹顶在前、嘉庚建筑群在后），历史上按顺序配对曾把嘉庚图错放到德旺位置。配对依据永远是描述，不是先后顺序。同页按顺序消费只允许发生在"无描述记录的手动英文名文件"上。

## 渲染与尺寸规范（宽度封顶策略）

**图片一律不显示文字描述**（figcaption 已取消）；alt 保留描述，供读屏器使用。宽度、居中由 CSS 统一处理，构建输出**不得带任何内联样式**。

### 核心策略：max-width 封顶，而不是按比例拉大
普通插图若原图小于上限，按**原图大小**显示，绝不强行放大（放大小图会发糊）。宽屏观感、窄屏随文字流收缩、原图本身小于上限时不拉伸，三者由以下两层规则同时满足：

```css
/* 通用：所有真实插图 */
.fig-photo { width: 80%; max-width: 573px; text-align: center; }  /* 桌面等效 4/5 观感，封顶 */
.fig-photo img { display: block; width: 100%; height: auto; }

/* App 图标等小图：原图接近 1:1 显示，不被拉大 */
.fig-icon { max-width: 180px; }

/* 纸质版装饰性小插图（"标题旁""右上方"等位置描述）：比图标更小巧 */
.fig-deco { max-width: 160px; }
```

### 构建脚本的自动分类（与 CSS 配套，勿拆散）
构建时按**占位符描述**自动给 figure 加 class（优先级从上到下）：
- **手动档位覆盖**（`MANUAL_CLASS_OVERRIDES` 字典，按描述精确匹配）→ 优先于一切关键词规则。用于自动关键词无法区分的特殊图（如"公交站台与公交车的卡通插画"这类**装饰小插画**与第 15 章"三人讨论交流的插画"正文大图都叫"插画"，必须靠人工点名）；
- 描述**含"图标"** → `class="fig-photo fig-icon"`（App 图标 180px 封顶）；
- 描述**含"插图"**，或**含位置词**（`标题旁`/`右上方`/`页面中部`/`右下角`）→ `class="fig-photo fig-deco"`（装饰性小插图 160px 封顶）；
- 其余 → `class="fig-photo"`（普通插图 573px 封顶）。

⚠️ 装饰小图覆盖范围：02/03 章"标题旁为xxx插图"、04 章"右下角书本与梯子插画"、05 章"排球插图"、07 章"卡通插画/立体插画"（手动点名）等**纸质版装饰元素**都归 160px；15 章"三人讨论交流的插画"等**正文大插画**、照片、**线路图/地图**（如南强二号线线路图）不含上述词，走 573px。三档 class 规则与 CSS 是配套的：改了构建脚本的 class 输出而不改 CSS（或反之），特调就会失效。

### 验证要点
- 图标类 figure 渲染宽度 ≈180px（`fig-icon`）、装饰小图 ≈160px（`fig-deco`）、普通插图桌面 ≈573px（或原图更小值）；
- 窄屏（如 390px 视口）下图片应收缩到文字流 80% 且**无横向溢出**。

## 防错清单
- [ ] 构建输出有 `[同步]` / `[图] 章XX 第X页 已匹配` 记录
- [ ] 源目录 `手册插入图片/` 已被清空（图是**剪切**不是拷贝）
- [ ] 有 `!! 无法匹配` 时已向用户报告
- [ ] `content.js` 版本号已 +1
- [ ] 浏览器刷新后 `.fig-photo` 数量 = 本次配对的图数，且位置正确
- [ ] 同页多占位符的章节已逐一看过，无错位
- [ ] 图标类 figure 渲染宽度 ≈180px、装饰小图 ≈160px、普通插图桌面 ≈573px（或原图更小值）、窄屏无溢出
